## Known design divergences and limits

The `ServedModel` consumer has no authoritative producer in the inspected
target; a requested model must not be treated as a served route. First-meaningful-output
timing is not ported, and existing TTFT is not equivalent. Built-in voice clip
transcription remains disabled unless a host supplies a transcriber; skills
responses expose no scan errors from the shell backend. Older upstream OTLP,
TLS, feedback and upload fixtures are not active in this fork.

The upstream snapshot wires a gated accelerator factory seam into local session
spawning, but contains no production factory installation; its default uses
LocalFs and `rg`, as does the fork. Custom embedded accelerators remain
unsupported in the fork because its session spawn does not use that factory seam.

The diagnostic listener cannot distinguish a trusted host from an unsandboxed
same-UID command. A planted persistent handler could survive a later enforce
transition; mutable broker routes remain unhosted until a suitable caller and
state lifetime boundary exists. Proxying alone is not an OS network boundary.
A denial persisted by another session or process is observed on reload, with no
instant cross-session revocation guarantee.

User-entered direct Bash commands retain the sandbox launch hook, but bypass the
model-tool adapter that binds the owner card and approved retry. A denied direct
command therefore does not get that adapter's card/retry flow. The inspected
upstream target uses the same direct terminal path.

The memory manifest budget is process-global: when concurrent sessions use
different `compact_index_enabled` settings, the last session to configure it
determines the budget used by later capture, dream and access writers. This is
a source-level interaction, not an observed default-behavior failure; defaults
are off and the target uses the same global mechanism. Prompt injection uses
its own session setting.

The ACP sandbox transport now sends a hold-specific interaction-resolved
notification when a network hold is withdrawn; that path still needs integrated
verification. The separate hub transport has no card-withdrawal wire operation:
when a hold ends locally, its late response is ignored, but its remote card
cannot yet be dismissed through that transport.

The upstream permission-rule crate extraction was not replayed wholesale;
the fork retains its permission actor and local rule implementation. The
snapshot provides sandbox status, mode and grant APIs, but inspection found
no production RPC dispatch to them in either snapshot or fork; references
to those RPC names are comments and tests, not evidence of an upstream
host. In-process mode writes are fenced, but external file edits are not
atomically fenced. Sandbox
profile resolution snapshots the hook write-deny state at engagement; later
hook-source changes require a live-refresh security review. A failed profile
resolution requires re-engagement to retry.

The fork retains its plan edit gate, provider-local auth and opaque history,
Code Mode transport/rendering, message authority, exact-task finalization and
Open Grok state paths. `xai-grok-login`, wholesale cloud-config and external
migration extractions, and the upstream xAI WinGet instruction are not adopted
as replacements for fork behavior. Other upstream hunks still need review;
the table is not an exhaustive parity certification.

## Metadata decisions

Both snapshots pin Rust 1.94.0. The fork retains its minimal native toolchain
profile instead of importing upstream's extra cross-target installation.
Upstream's Clippy change only relaxes invalid-path handling for two spawn bans;
no observed fork diagnostic requires changing its current ban. `SOURCE_REV`
is not present in the fork, the generated root `Cargo.toml` remains read-only,
and `OPEN_GROK_VERSION` is not bumped for this source replay. Upstream release
notes are not copied into fork release metadata while features remain unproven.
